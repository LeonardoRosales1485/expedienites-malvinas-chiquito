1. Introducción
El presente documento define un análisis funcional integral para la implementación de un Sistema de Expediente
Digital Municipal, tomando como base los circuitos administrativos vigentes y el organigrama funcional municipal.
Los documentos analizados muestran que los circuitos administrativos se encuentran estructurados por
repartición interviniente, actuación y plazo estimado en días. El objetivo del sistema no es modificar la lógica
administrativa vigente, sino digitalizarla, hacerla trazable y permitir su control operativo, legal y funcional.
El Decreto 2239/21 establece la necesidad de diseñar, revisar, monitorear y auditar los circuitos administrativos,
así como capacitar a los agentes intervinientes. Por lo tanto, el sistema debe funcionar como soporte tecnológico
para esos circuitos y como herramienta de control de cumplimiento.
2. Objetivo del sistema
Implementar una plataforma que permita gestionar expedientes municipales desde su inicio hasta su cierre y
archivo, respetando las áreas intervinientes, las actuaciones previstas, las validaciones requeridas, los plazos
definidos y los actos administrativos que correspondan.
• Digitalizar la creación, derivación, intervención, aprobación, ejecución y archivo de expedientes.
• Centralizar documentación, formularios, dictámenes, actos administrativos y constancias.
• Garantizar trazabilidad completa por expediente, área, usuario, fecha y acción.
• Controlar plazos y detectar desvíos respecto del circuito aprobado.
• Permitir aprobaciones jerárquicas por área cuando corresponda.
• Facilitar la generación, firma, registro y notificación de actos administrativos.
• Brindar reportes para gestión, auditoría y mejora continua.
3. Alcance funcional
• Alta y caratulación de expedientes.
• Carga de solicitudes externas e internas.
• Gestión documental con adjuntos, formularios, informes y constancias.
• Derivación entre áreas municipales según circuito configurado.
• Intervenciones técnicas, económicas, contables, tributarias y legales.
• Generación de decretos, resoluciones, disposiciones, convenios, certificados y autorizaciones.
• Circuito de firmas y refrendos.
• Notificaciones al interesado y a áreas internas.
• Seguimiento de estados y plazos.
• Cierre, archivo y auditoría del expediente.
4. Criterio funcional general
El análisis de los circuitos permite identificar que no existe un único flujo idéntico para todos los trámites. Lo que
existe es una estructura común que se adapta según el tipo de expediente. Por eso, la solución recomendada es
un motor de workflow configurable.
Cada tipo de trámite debe tener definido su recorrido: área de inicio, documentación requerida, validaciones,
áreas intervinientes, plazos, acciones permitidas, condiciones de avance, posibles devoluciones, acto
administrativo final y área de cierre.

6.2 Validación inicial
Antes de caratular, el sistema debe confirmar que el trámite tenga datos mínimos, documentación inicial,
solicitante identificado, área competente y circuito asociado.
• Si falta documentación obligatoria, el trámite queda observado y vuelve al interesado o al área originante.
• Si no corresponde iniciar expediente, se rechaza fundadamente.
• Si está correcto, se habilita la caratulación formal.
6.3 Caratulación
La caratulación formaliza la existencia del expediente. Debe generar número único, año, tipo de trámite, iniciador,
área originante, área responsable inicial, objeto, fecha de inicio, estado inicial, circuito asociado y plazo estimado.
6.4 Derivación inicial
Una vez caratulado, el expediente debe enviarse al área competente según el tipo de trámite. La derivación
puede ser automática por configuración del circuito o manual con justificación, siempre dejando trazabilidad.

11. Reglas de negocio principales
11.1 Reglas de inicio
• Todo trámite debe tener tipo de expediente.
• Todo expediente debe tener un área responsable inicial.
• Todo expediente debe estar asociado a un circuito aprobado o configurable.
• No se debe caratular si faltan datos mínimos.
• Toda presentación debe generar constancia.
11.2 Reglas de documentación
• Cada trámite debe tener una matriz de documentación obligatoria, opcional y condicional.
• Si falta documentación obligatoria, el trámite queda observado.
• Cada documento debe registrar fecha, usuario, área, versión y tipo documental.
• Los informes, certificados, dictámenes y constancias deben quedar incorporados al expediente.
11.3 Reglas de derivación
• El expediente debe circular según el flujo configurado.

• Toda derivación debe registrar fecha de salida, fecha de entrada, área origen y área destino.
• Las áreas pueden devolver por observación al área anterior o al iniciador, según circuito.
• Toda intervención no prevista debe quedar registrada como intervención excepcional.
11.4 Reglas de plazos
• Cada etapa debe tener plazo estimado.
• El sistema debe calcular vencimientos y alertas.
• Los expedientes vencidos deben quedar marcados para seguimiento.
• La auditoría debe poder detectar desvíos por plazo y por giro incorrecto.
11.5 Reglas de aprobación
• Cada área debe poder aprobar, observar o rechazar.
• La aprobación debe registrar usuario, cargo, área, fecha y comentario.
• Cuando exista aprobación jerárquica, el expediente debe pasar de agente a responsable o director.
• Sin aprobación del nivel requerido, el expediente no debe avanzar.
11.6 Reglas de acto administrativo
• El acto se genera solo cuando las etapas previas están completas.
• Debe existir plantilla según tipo de acto.
• Debe existir circuito de firma.
• No se puede registrar acto sin firma requerida.
• El acto firmado debe incorporarse al expediente.
11.7 Reglas de cierre
• Solo se puede cerrar expediente si tiene resultado final.
• El cierre debe registrar motivo y usuario.
• No debe permitirse modificar expediente cerrado, salvo reapertura autorizada.
• El archivo debe conservar historial completo.

13. Cómo iniciaría el expediente
13.1 Portal externo
Para vecinos, comerciantes, empresas, beneficiarios o adjudicatarios. El usuario ingresa, selecciona trámite,
completa datos, adjunta documentación y envía. El sistema genera una presentación y la remite a revisión inicial.
13.2 Módulo interno de repartición
Para expedientes iniciados por áreas municipales. El agente selecciona tipo de expediente, carga nota, informe,
documentación y proyecto de acto si corresponde. Luego remite a Mesa de Entradas para caratulación.
13.3 Inicio desde otro expediente
Cuando un expediente cerrado o en trámite genera una nueva actuación. Por ejemplo, recupero de inmueble que
genera adjudicación, plano no conforme que genera regularización, deuda no cancelada que genera apremio o
subsidio otorgado que genera legajo de rendición.

15. Recomendación funcional final
La mejor solución no es construir un sistema rígido por cada trámite, sino un Sistema de Expediente Digital con
motor configurable de circuitos. Esto permitiría digitalizar circuitos distintos sin desarrollar desde cero cada
proceso.

• Objeto.

• Estado resultante.

16. Conclusión
Los circuitos municipales analizados ya cuentan con una lógica administrativa sólida: cada expediente se mueve
por reparticiones específicas, con actuaciones definidas, plazos estimados y actos administrativos finales. El
sistema debe respetar esa lógica y convertirla en una herramienta digital que permita seguimiento, trazabilidad,
control de plazos y auditoría.
El flujo ideal inicia con una solicitud externa o interna, se caratula formalmente, atraviesa las áreas técnicas,
económicas y legales que correspondan, genera el acto administrativo necesario, ejecuta la decisión, notifica al
interesado y finaliza con cierre y archivo del expediente.
